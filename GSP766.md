Paste one block at a time and wait for the prompt to come back before pasting the next. Nothing in this guide needs editing: every value is detected for you.

1. Wait for the blue "Provisioning Lab Resources" message to disappear before you start (about 5 minutes).
2. Testing as the team-a-dev account switches your whole Cloud Shell to that account. Task 3 switches you back automatically. If later steps say "permission denied", run `gcloud config set account` followed by your student email.

## Setup

```bash
gcloud config get-value project > ~/project
gcloud config get-value account > ~/student
gcloud container clusters list --filter="name=multi-tenant-cluster" --format="value(location)" > ~/zone
head ~/project ~/student ~/zone
```

All three values must print. If the zone is empty, the lab is still provisioning, so wait a minute and run the block again.

## Task 3 – Access control

Block 1 – give team-a-dev access to team-a only:

```bash
cd ~/gke-qwiklab
kubectl config set-context --current --namespace=team-a
gcloud projects add-iam-policy-binding `cat ~/project` \
  --member=serviceAccount:team-a-dev@`cat ~/project`.iam.gserviceaccount.com \
  --role=roles/container.clusterViewer --condition=None > /dev/null && echo iam-done
kubectl create role pod-reader --resource=pods --verb=watch --verb=get --verb=list -n team-a
kubectl create -f developer-role.yaml
kubectl create rolebinding team-a-developers --role=developer \
  --user=team-a-dev@`cat ~/project`.iam.gserviceaccount.com -n team-a
gcloud iam service-accounts keys create /tmp/key.json --iam-account team-a-dev@`cat ~/project`.iam.gserviceaccount.com
```

Check my progress: Access Control in Namespaces (25 points)

Block 2 – test it as team-a-dev, then switch back to you:

```bash
gcloud auth activate-service-account --key-file=/tmp/key.json
gcloud container clusters get-credentials multi-tenant-cluster --zone `cat ~/zone` --project `cat ~/project`
echo "=== team-a (works) ==="
kubectl get pods --namespace=team-a
echo "=== team-b (Forbidden) ==="
kubectl get pods --namespace=team-b
gcloud config set account `cat ~/student`
gcloud container clusters get-credentials multi-tenant-cluster --zone `cat ~/zone` --project `cat ~/project`
echo "=== you are now ==="
gcloud config get-value account
```

The last line must show your student email. Team-a lists a pod; team-b says Forbidden. That's the point of the test.

## Task 4 – Resource quotas

Block 1 – limit team-a to 2 pods (the third pod is supposed to fail):

```bash
cd ~/gke-qwiklab
kubectl create quota test-quota --hard=count/pods=2,count/services.loadbalancers=1 --namespace=team-a
kubectl run app-server-2 --image=quay.io/centos/centos:9 --namespace=team-a -- sleep infinity
kubectl run app-server-3 --image=quay.io/centos/centos:9 --namespace=team-a -- sleep infinity
kubectl describe quota test-quota --namespace=team-a
```

app-server-3 shows "exceeded quota". That's expected.

Block 2 – raise the limit to 6 pods, then add the CPU and memory quota:

```bash
cd ~/gke-qwiklab
kubectl patch resourcequota test-quota -n team-a --type=merge -p '{"spec":{"hard":{"count/pods":"6"}}}'
kubectl create -f cpu-mem-quota.yaml
kubectl create -f cpu-mem-demo-pod.yaml --namespace=team-a
sleep 5
kubectl describe quota test-quota --namespace=team-a
kubectl describe quota cpu-mem-quota --namespace=team-a
```

test-quota shows a Hard limit of 6 pods. cpu-mem-quota shows 400m CPU limits and 100m CPU requests used.

Check my progress: Resource Quotas (25 points)

## Task 5 – Usage metering and the cost breakdown (40 points)

This task has 5 steps: A, B and C run in Cloud Shell, D runs in the BigQuery Console, and E runs in Data Studio.

Step A – turn on usage metering:

```bash
gcloud container clusters update multi-tenant-cluster --zone `cat ~/zone` --resource-usage-bigquery-dataset cluster_dataset
```

Step B – build your cost breakdown query (your project ID is filled in automatically):

```bash
cd ~
sed \
  -e "s/.{fullGCPBillingExportTableID}/`cat ~/project`.billing_dataset.gcp_billing_export_v1_xxxx/g" \
  -e "s/.{projectID}/`cat ~/project`/g" \
  -e "s/.{datasetID}/cluster_dataset/g" \
  -e "s/.{startDate}/2020-10-26/g" \
  ~/gke-qwiklab/usage_metering_query_template.sql > ~/cost_breakdown_query.sql
grep -c "{projectID}\|{datasetID}\|{startDate}\|fullGCPBillingExportTableID" ~/cost_breakdown_query.sql
wc -l ~/cost_breakdown_query.sql
```

The first number must be 0 (no placeholders left). The file is about 295 lines.

Step C – create the cost breakdown table:

```bash
cd ~
bq query --project_id=`cat ~/project` --use_legacy_sql=false \
  --destination_table=cluster_dataset.usage_metering_cost_breakdown --replace=true \
  "`cat ~/cost_breakdown_query.sql`" > /dev/null && echo table-created
```

You should see table-created.

Step D – create the scheduled query in the BigQuery Console. This replaces the lab's broken command.

First, copy the query. Use Plan A. Only use Plan B if Plan A doesn't work.

Plan A – copy your own query from the Cloud Shell Editor (recommended):

1. In Cloud Shell, click Open Editor.
2. In the file list on the left, click cost_breakdown_query.sql. It's in your home folder, not inside gke-qwiklab.
3. Click inside the file, press Ctrl+A, then Ctrl+C.
4. Your project ID is already in it, so you can paste it as is.

Plan B – copy the ready-made query from this repo:

1. Open GSP766_cost_breakdown_query.sql in this repo and click Copy raw file (the two-squares icon).
2. In Cloud Shell, run `cat ~/project` and note your project ID.
3. After you paste the query into BigQuery (next list, step 3), press Ctrl+H.
4. Find: YOUR_PROJECT_ID. Replace: your project ID. Click Replace All. It replaces 4 places.
5. Search for YOUR_PROJECT_ID again to check that none are left.

Then schedule it:

1. In the Console, go to BigQuery.
2. Click + to open a new query tab.
3. Paste the query (Ctrl+V). Plan B users: do the Ctrl+H replace now. Don't click Run.
4. A green check at the top right of the editor means the query is complete.
5. Click Schedule, then Create new scheduled query.
6. Name: GKE Usage Metering Cost Breakdown Scheduled Query
7. Repeat frequency: Days.
8. At: type a UTC time, for example 23:30. This field is required. If it's empty, the form says "Form invalid".
9. Leave Start now and End never selected.
10. Tick Set a destination table for query results.
11. Dataset: cluster_dataset. Table Id: usage_metering_cost_breakdown.
12. Write preference: Overwrite table.
13. Click Save. If a sign-in popup appears, choose your student account and click Allow.

Step E – connect the table in Data Studio:

1. In Cloud Shell, print your custom query with your project ID filled in, and copy it:

```bash
printf 'SELECT * FROM `%s.cluster_dataset.usage_metering_cost_breakdown`\n' "`cat ~/project`"
```

2. Open the Data Studio Data Sources page from the lab's link ("Open the Data Studio Data Sources page").
3. Top left: Create, then Data Source.
4. If you see the account setup window, pick your country, type any company name, tick the box, and click Continue. Answer No to all the email preferences, then click Continue.
5. Select BigQuery from the connector list.
6. Click Authorize and allow access with your student account.
7. Top left: rename Untitled Data Source to GKE Usage.
8. First column: click CUSTOM QUERY.
9. Projects column: click your project ID.
10. Paste the query from step 1 into the custom query box.
11. Top right: click CONNECT.

You'll see the GKE Usage page listing the table's fields (amount, cluster_location, cluster_name and so on).

Wait about one minute, then click Check my progress: Monitoring GKE and GKE Usage Metering (40 points). If it shows 20/40, wait another minute and click again.
