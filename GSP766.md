## Task 3 – Access control

Block 1 – give team-a-dev access to team-a only:

```bash
cd ~/gke-qwiklab
kubectl config set-context --current --namespace=team-a
gcloud projects add-iam-policy-binding `cat ~/project` \
  --member=serviceAccount:team-a-dev@`cat ~/project`.iam.gserviceaccount.com \
  --role=roles/container.clusterViewer --condition=None > /dev/null && echo iam-done
kubectl create role pod-reader --resource=pods --verb=watch --verb=get --verb=list -n team-a
kubectl create -f developer-role.yaml
kubectl create rolebinding team-a-developers --role=developer \
  --user=team-a-dev@`cat ~/project`.iam.gserviceaccount.com -n team-a
gcloud iam service-accounts keys create /tmp/key.json --iam-account team-a-dev@`cat ~/project`.iam.gserviceaccount.com
```

Check my progress: Access Control in Namespaces (25 points)

Block 2 – test it as team-a-dev, then switch back to you:

```bash
gcloud auth activate-service-account --key-file=/tmp/key.json
gcloud container clusters get-credentials multi-tenant-cluster --zone `cat ~/zone` --project `cat ~/project`
echo "=== team-a (works) ==="
kubectl get pods --namespace=team-a
echo "=== team-b (Forbidden) ==="
kubectl get pods --namespace=team-b
gcloud config set account `cat ~/student`
gcloud container clusters get-credentials multi-tenant-cluster --zone `cat ~/zone` --project `cat ~/project`
echo "=== you are now ==="
gcloud config get-value account
```

The last line must show your student email. Team-a lists a pod; team-b says Forbidden. That's the point of the test.

## Task 4 – Resource quotas

Block 1 – limit team-a to 2 pods (the third pod is supposed to fail):

```bash
cd ~/gke-qwiklab
kubectl create quota test-quota --hard=count/pods=2,count/services.loadbalancers=1 --namespace=team-a
kubectl run app-server-2 --image=quay.io/centos/centos:9 --namespace=team-a -- sleep infinity
kubectl run app-server-3 --image=quay.io/centos/centos:9 --namespace=team-a -- sleep infinity
kubectl describe quota test-quota --namespace=team-a
```

app-server-3 shows "exceeded quota". That's expected.

Block 2 – raise the limit to 6 pods, then add the CPU and memory quota:

```bash
cd ~/gke-qwiklab
kubectl patch resourcequota test-quota -n team-a --type=merge -p '{"spec":{"hard":{"count/pods":"6"}}}'
kubectl create -f cpu-mem-quota.yaml
kubectl create -f cpu-mem-demo-pod.yaml --namespace=team-a
sleep 5
kubectl describe quota test-quota --namespace=team-a
kubectl describe quota cpu-mem-quota --namespace=team-a
```

test-quota shows a Hard limit of 6 pods. cpu-mem-quota shows 400m CPU limits and 100m CPU requests used.

Check my progress: Resource Quotas (25 points)

## Task 5 – Usage metering and the cost breakdown (40 points)

Three parts, in order: Cloud Shell, then BigQuery, then Data Studio. Do all three before you click Check.

### Part 1 – Cloud Shell

Block 1 – turn on usage metering:

```bash
gcloud container clusters update multi-tenant-cluster --zone `cat ~/zone` --resource-usage-bigquery-dataset cluster_dataset
```

Block 2 – build your query file (your project ID is filled in for you):

```bash
cd ~
sed \
  -e "s/.{fullGCPBillingExportTableID}/`cat ~/project`.billing_dataset.gcp_billing_export_v1_xxxx/g" \
  -e "s/.{projectID}/`cat ~/project`/g" \
  -e "s/.{datasetID}/cluster_dataset/g" \
  -e "s/.{startDate}/2020-10-26/g" \
  ~/gke-qwiklab/usage_metering_query_template.sql > ~/cost_breakdown_query.sql
grep -c "{projectID}\|{datasetID}\|{startDate}\|fullGCPBillingExportTableID" ~/cost_breakdown_query.sql
wc -l ~/cost_breakdown_query.sql
```

The first number must be 0. The file is about 295 lines.

Block 3 – create the cost table:

```bash
cd ~
bq query --project_id=`cat ~/project` --use_legacy_sql=false \
  --destination_table=cluster_dataset.usage_metering_cost_breakdown --replace=true \
  "`cat ~/cost_breakdown_query.sql`" > /dev/null && echo table-created
```

You should see table-created.

### Part 2 – BigQuery: create the scheduled query

The lab's bq command for this is broken (see trap 3), so you do it in the Console instead.

1. In Cloud Shell, click Open Editor.
2. In the file list on the left, click cost_breakdown_query.sql. It's in your home folder, not inside gke-qwiklab.
3. Click inside the file, press Ctrl+A, then Ctrl+C.
4. In the Console, open BigQuery and click + to open a new query tab.
5. Click inside the editor and press Ctrl+V. Don't click Run.
6. Look for the green check at the top right of the editor. If you see red instead, the copy broke: use the Backup section at the end of this guide, then come back to step 7.
7. Click Schedule, then Create new scheduled query.
8. Name: GKE Usage Metering Cost Breakdown Scheduled Query
9. Repeat frequency: Days.
10. At: type a UTC time, for example 23:30. It's required. If it's empty you get "Form invalid".
11. Leave Start now and End never selected.
12. Tick Set a destination table for query results.
13. Dataset: cluster_dataset. Table Id: usage_metering_cost_breakdown.
14. Write preference: Overwrite table.
15. Click Save. If a sign-in popup appears, choose your student account and click Allow.

### Part 3 – Data Studio: connect the table

1. In Cloud Shell, run this and copy the line it prints:

```bash
printf 'SELECT * FROM `%s.cluster_dataset.usage_metering_cost_breakdown`\n' "`cat ~/project`"
```

2. Open the Data Studio Data Sources page from the lab's link.
3. Top left: Create, then Data Source.
4. If an account setup window appears: pick your country, type any company name, tick the box, Continue, answer No to all emails, Continue.
5. Choose BigQuery from the connectors.
6. Click Authorize and allow access with your student account.
7. Top left: rename Untitled Data Source to GKE Usage.
8. First column: CUSTOM QUERY.
9. Projects column: your project ID.
10. Paste the line from step 1 into the query box.
11. Top right: CONNECT.

You'll see a list of fields (amount, cluster_location, cluster_name and so on).

Wait one minute, then click Check my progress: Monitoring GKE and GKE Usage Metering (40 points). If it shows 20/40, wait another minute and click again.

What to fix, by the line that is wrong:

1. Wrong account: the first line of this block already switched you back. Run the block again.
2. Empty: run Step A again.
3. "Not found": run Step B and Step C again.
4. Empty list: the scheduled query was never saved. Do Step D again and make sure you click Save, not just Schedule. If it's listed but its name is different, delete it in BigQuery > Scheduled queries and create it again with the exact name.

If all four are right, do Step E (Data Studio) if you skipped it, wait one minute, and check again.
